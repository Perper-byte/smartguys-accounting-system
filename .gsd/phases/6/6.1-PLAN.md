# Plan 6.1: Dynamic Accounting Calendar Service & Closed Period Guard

## Objective
Create the `AccountingPeriodService` to dynamically generate and manage 12 monthly accounting periods for any fiscal/calendar year, and enforce a strict transaction posting guard in `LedgerService` that blocks any entries dated inside a `CLOSED` accounting period.

      - Updates period status in `SystemSetting.accounting_calendar` and writes an audit log.
    - Expose IPC channels `calendar:get`, `calendar:update-status` in `src/main/index.ts` and `src/preload/index.ts`.

<task type="auto">
  <name>Add strict CLOSED period transaction guard to LedgerService</name>
  <files>src/main/services/ledger.service.ts, src/main/services/accounting-period.service.ts</files>
  <action>
    In `src/main/services/ledger.service.ts`:
    - Add helper `checkPeriodClosed(date: Date)`:
      - Calls `AccountingPeriodService.isDateInClosedPeriod(date)`.
      - If the date falls within a period marked `CLOSED`, throw Error:
        `"PERIOD CLOSED: Accounting period for this date is CLOSED. Transactions cannot be posted or modified in a closed period."`
    - Apply `checkPeriodClosed(entryDate)` in `recordEntry`, `updateEntry`, and void handlers before any write occurs.
    - Ensure closed period cannot be bypassed by Manager Override PIN (only soft locks can be bypassed with PIN; closed periods require explicit reopening).
  </action>
  <verify>npm run build</verify>
  <done>LedgerService enforces hard block against posting transactions dated in closed accounting periods.</done>
</task>
